# HanaBi UI 设计与维护要求

记录日期：2026-10-21。本文与 [开场动画设计要求](开场动画设计要求.md)、[角色主题索引](角色主题索引.md) 一起维护。角色专属方案写进对应的 `<角色名>_design.md`，公共交互要求记录在这里。

## 界面定位

当前交付是本地界面与交互演示，不需要接入功能后端。各功能页应有完整布局、合理控件和可见的交互反馈，不能只有空白页面。主题选择集中在主题页，不能散落在无关功能页。

## 主题与背景

- 角色主题围绕角色的服饰、纹饰、材质、性格和壁纸创作，不能只替换一组颜色。
- 角色界面需要适当透明，能看到所选择的壁纸与人物动态，同时保证文字和控件可读。
- 黑色与白色是独立基础主题，不继续露出角色壁纸。白色主题避免脏灰、厚重阴影。
- 保留背景已有的人物动态，包括眨眼、衣发摇曳和环境效果。不能用单张静态截图冒充完整动态壁纸。
- 侧栏使用从开场平滑停驻的同一元素 Logo，直接放置，不增加突兀的背景底块。

## 窗口与流畅度

- 窗口可以移动、调整大小，提供最小化、最大化和关闭按钮。
- 每个角色的三个窗口按钮都有与角色、壁纸匹配的造型和细节。
- 最小化有专门的退场动画，不能点击后直接消失；恢复和启动同样要自然。
- 启动不能闪出突兀的白底。页面切换、悬停、点击、主题切换与开场停驻都要连续、平滑。
- 点击某个控件不应导致其他无关控件闪烁；交互状态不能误共用。
- 动画的目标是用户所说的接近苹果原生应用的丝滑体验；不能把“可运行”当作视觉完成。

## 页面与人物示意

- 目标部位选择提供可点选的人体示意，反馈清楚，不靠无法理解或不能点击的装饰。
- 人体采用用户最终选择的极简、无脸模特样式，避免粗糙人物画和不合主题的复杂人像。
- 视觉页中的人物示意与其他功能页保持同一设计语言。
- 对用户提出的具体局部修改，优先直接编辑对应代码，避免无必要地打开或操作窗口。

## 可扩展主题库

- 保留原来的大长方形角色卡片、角色姓名以及姓名后面的短句。
- 按元素分类筛选，允许向下滚动；角色增加时扩展内容，不持续缩小卡片。
- 后续按全角色规模维护，同元素角色共用基础材质，但拥有独立 UI 和开场演出。
- 黑白基础主题与角色主题明确区分，放在基础主题区域。
- 字体大小在主题页调节，默认 112%，当前范围 100%–125%。
- 支持跟随当前主题、固定角色和随机角色启动，设置持久化；随机不包含黑白主题。

## 文件与交付

每个角色使用小写英文名或拼音目录，同目录维护 UI、开场和设计文档；公共布局、控件、材质、壁纸渲染保留在公共模块。详见 [角色主题索引](角色主题索引.md)。

只保留一个解决方案和统一的 `bin/Release/hanabi.exe`。预处理资源可直接用于 C++ 构建与运行，不要求用户运行 Python 制作工具。不将调试帧、重复可执行文件和临时预览放进项目目录。
